# 11v11 Roblox-Style Football Game — Implementation Plan

## Context
- Greenfield repo: `/workspace/app`, empty git on branch `kilo/bubbly-crystal-22y`.
- Target: browser-based 3D 11v11 football game playable on PC and mobile browsers, no install.
- Engine/stack (decided): **Three.js (WebGL) client + Socket.io/Node.js server**, HTML/CSS UI.
- Core features: PC/mobile detection, platform-specific controls, real-time multiplayer (11v11 rooms) + AI bots to fill slots, kit/weather/stadium selectors, good graphics without lag.

## Decisions (resolved)
| Area | Decision | Rationale |
|------|----------|-----------|
| Rendering | Three.js, WebGL1/2 | Runs on PC + mobile browsers; controllable performance |
| Multiplayer | Socket.io over WebSocket, Node.js + Express server | Real-time, works on all platforms, rooms/lobbies |
| Physics | Custom lightweight sphere/box physics (no heavy engine) | Predictable, low CPU, easy to sync over network |
| Netcode | Client input prediction + server reconciliation + snapshot interpolation for other players | Hides latency, keeps authoritative server |
| AI bots | Steering behaviors (seek/arrive/avoid) + finite-state machine (chase/attack/defend) + simple nav waypoints per stadium | No navmesh dependency; fills empty slots to 22 |
| Platform detection | `window.matchPointer`/touch presence + user-agent hint; explicit PC vs mobile toggle in settings | Detects device at load; allows override |
| Controls PC | WASD + mouse look/aim, space/shoot, shift/sprint, E/tackle, gamepad via Gamepad API | Standard football controls |
| Controls Mobile | Virtual joystick (left) + pass/shoot/tackle/sprint buttons (right) | Touch-friendly, thumb-zone safe |
| Graphics budget | Instanced meshes for players, directional light + shadows (PC on, mobile off/low), fog, LOD on distant players, cap ~60-100 draw calls, target 60fps PC / 30fps mobile | Meets "good graphics, no lag" on both |
| Quality presets | PC: high (shadows, AA, full LOD); Mobile: low (no shadows, reduced particle count, lower render scale) | Performance parity |
| Weather | Clear / Rain / Snow — particle system + ground material wetness + reduced ball roll on wet | Selectable via UI |
| Stadiums | 2–3 selectable environments (pitch size/goal/stands scale shared) | Low asset burden |
| Kits | Home/Away kit selector per team (color + material), stored per room | Selectable via UI |
| Match size | 11v11 = 22 players; bots fill empty slots; rooms cap at 22 | True 11v11 |

## Key modules & interfaces (implementation guidance)

### platform.js
```js
export const isMobile = () => /Android|webOS|iPhone|iPad|iPod|Mobile/i.test(navigator.userAgent)
  || (window.matchMedia && window.matchMedia('(pointer: coarse)').matches)
export const isPC = () => !isMobile()
export const controlScheme = () => isMobile() ? 'mobile' : 'pc'
```
Call at load; expose `setPreferredScheme('pc'\|'mobile')` override stored in localStorage.

### controls
- `pcControls.js`: listen `keydown/keyup` (WASD, Space, Shift, E), `pointerlock` for mouse aim, `gamepad` API read each frame. Output normalized `input` object `{x, z, shoot, pass, tackle, sprint, aimX, aimY}`.
- `mobileControls.js`: virtual joystick div (touchstart/move/end) → direction; fixed action buttons → shoot/pass/tackle/sprint. Prevent default on canvas to avoid scroll/zoom.

### networking / netcode
- Client sends `input` at 30Hz (or on change). Server runs authoritative simulation at 30Hz.
- Server broadcasts full snapshot (ball + all players) at 20Hz; client interpolates remote players between snapshots; local player predicted.
- Room protocol: `joinRoom`, `leaveRoom`, `startMatch`, `syncState`, `goalScored`, `matchEnd`.
- Bots run server-side (authoritative) so AI is consistent across clients.

### graphics budget
- Use `THREE.InstancedMesh` for all outfield players (22 instances, one draw call).
- Shadows: `castShadow`/`receiveShadow` only on PC preset; mobile uses `ShadowMap` disabled.
- Render scale: `renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))` PC, cap 1.5 mobile.
- LOD: swap player geometry to lower-detail buffer geometry beyond ~25 studs.
- Particles: rain/snow capped at ~200 particles mobile, ~800 PC.

### AI (server-side `bots/bot.js`)
- FSM states: `idle`, `chaseBall`, `moveToPosition`, `attack`, `defend`, `shoot`.
- Steering: seek target, arrive (slow near target), avoid other players/ball.
- Position roles (GK, CB, LB/RB, CM, LM/RM, ST) with home positions per team; formation 4-4-2.
- Bot difficulty scales pass accuracy and reaction time.

## Risks & mitigations
| Risk | Mitigation |
|------|------------|
| 22 players + ball over WebSocket lag | Snapshot at 20Hz, input compression, delta only on change, room region-aware (single region MVP) |
| Mobile thermal/battery drain | Low preset disables shadows, caps particles/render scale, target 30fps |
| Three.js physics drift between client/server | Server authoritative; client reconciles position on mismatch (snap back) |
| Touch zoom/scroll breaking controls | `touch-action: none` on canvas, `preventDefault` on joystick/buttons |
| 11v11 player crowding on pitch | Formation spacing rules, avoid steering, pitch bounds clamping |

## Validation steps (implementation agent to run)
1. `npm install` and `npm run dev` (or equivalent) — client + server start without errors.
2. Open on desktop Chrome: join/create room, verify 11v11 with bots filling, kit/weather/stadium selectors apply, PC controls move/shoot/tackle.
3. Open on mobile Chrome (or DevTools mobile emulation): verify virtual joystick + buttons render, no page scroll/zoom, mobile graphics preset active (no shadows).
4. Verify bot fill: create room alone → bots spawn until 22 total; bots chase/attack/defend.
5. Verify goal logic: ball into goal → `goalScored`, scoreboard updates, match resets.
6. Verify network: open two browser tabs/windows, join same room, observe remote player interpolation + prediction.
7. Frame budget: Chrome DevTools Performance — sustained ~60fps PC / ~30fps mobile, draw calls ≤100.
